# Stroke V1 — Firestore Data Model & Reliability Specification

This document defines the authoritative Firebase Cloud Firestore schema, security boundaries, migration architecture, and reliability guarantees for the Stroke V1 production stack.

---

## 1. Identity & Data Ownership Model

Stroke V1 strictly enforces **Firebase Auth UID** as the sole user ownership key across the entire application stack.

- **Zero Email-Based Ownership:** Legacy document paths keyed by user email addresses (e.g., `users/alice@example.com`) are permanently deprecated and restricted to historical migration.
- **Root Collection:** `users/{uid}`
- **Subcollections:** All user-owned data is stored in dedicated subcollections nested beneath the user's root document.
- **Stateless Verification:** All server-side operations derive the user's UID directly from the cryptographically verified Firebase ID token via `auth_service.get_current_user`. Caller-supplied emails in query parameters, request bodies, or headers are never trusted to establish identity or document ownership.

```
/users/{uid}
    ├── records/{record_id}            (STRK-BAT-001..005 VFX records)
    ├── memory/{memory_id}              (AI interaction memory nodes, 100 MB quota)
    ├── feed_state/current              (Sequential feeding state & synthesis)
    ├── chats/{session_id}              (Conversation histories & message logs)
    ├── projects/{project_id}          (Workspace paths & Roblox project bindings)
    ├── settings/preferences           (UI themes, keybindings, editor settings)
    └── integrations/{provider}         (OAuth metadata, e.g., GitHub connection)
```

## 2. Collection Schemas & Data Constraints

### 2.1 User Root Document: `/users/{uid}`
Stores core profile information, telemetry flags, and quota accounting summaries.

| Field | Type | Description | Constraints |
| :--- | :--- | :--- | :--- |
| `uid` | `string` | Firebase Auth UID | Immutable; matches document ID |
| `email` | `string \| null` | Verified email address | Max 256 chars |
| `display_name` | `string \| null`| User display name | Max 100 chars |
| `database_fed` | `boolean` | Flag indicating 5-cycle ingestion completion | Default: `false` |
| `memory_bytes_used_estimate` | `integer` | Estimated bytes used across `memory/` subcollection | Min: `0`, Max: `104,857,600` (100 MB) |
| `memory_count` | `integer` | Count of active memory records | Min: `0` |
| `quota_bytes` | `integer` | Maximum memory quota in bytes | Constant: `104,857,600` |
| `github_token` | `string \| null`| Encrypted GitHub PAT (machine-level cipher) | Encrypted format only |
| `created_at` | `timestamp \| string` | ISO timestamp of document creation | Immutable |
| `updated_at` | `timestamp \| string` | ISO timestamp of last document update | Updated on write |

### 2.2 VFX Ingestion Records: `/users/{uid}/records/{record_id}`
Stores structural records generated by the 5-Cycle VFX Database Ingestion engine (`STRK-BAT-001` through `STRK-BAT-005`).

| Field | Type | Description | Constraints |
| :--- | :--- | :--- | :--- |
| `record_id` | `string` | Unique record ID | Format: `STRK-BAT-[0-9]{3}` |
| `uid` | `string` | Owning Firebase UID | Matches parent doc UID |
| `cycle` | `integer` | Feeding cycle index | Between `1` and `5` |
| `vfx_name` | `string` | Stage name (e.g. "Cosmic Domain Blast") | Max 100 chars |
| `metric_load` | `number` | Processing load percentage | Between `0.0` and `100.0` |
| `status` | `string` | Ingestion status | Must equal `"optimized"` |
| `integrity_hash` | `string` | 8-byte hexadecimal hash | Length: 8-16 chars |
| `data_slice_summary` | `string` | Summary of ingested VFX parameters | Max 1,000 chars |
| `ai_synthesis` | `string` | AI synthesis output for this stage | Max 5,000 chars |
| `created_at` | `timestamp \| string` | Ingestion timestamp | Valid ISO string |

### 2.3 AI Interaction Memory: `/users/{uid}/memory/{memory_id}`
Stores summarized interaction memories with pre-write quota enforcement.

| Field | Type | Description | Constraints |
| :--- | :--- | :--- | :--- |
| `memory_id` | `string` | Unique memory identifier | Format: `MEM-[0-9]{14}-[a-f0-9]{8}` |
| `uid` | `string` | Owning Firebase UID | Matches parent doc UID |
| `summary` | `string` | AI interaction summary | Max 1,000 chars |
| `prompt_excerpt` | `string` | Truncated user prompt | Max 500 chars |
| `reply_excerpt` | `string` | Truncated AI assistant response | Max 500 chars |

| `god_tier_vfx_learned`| `boolean`| Flag indicating learned VFX pattern | Boolean |
| `vfx_model_name` | `string \| null`| Learned VFX model name | Max 100 chars |
| `byte_size_estimate` | `integer`| Estimated serialized byte size | Min: `1`, Max: `104,857,600` |
| `created_at` | `timestamp \| string` | Creation timestamp | Valid ISO string |

### 2.4 Feed Cycle State: `/users/{uid}/feed_state/current`
Tracks the active progression of the 5-Cycle Feed Engine to prevent out-of-order execution.

| Field | Type | Description | Constraints |
| :--- | :--- | :--- | :--- |
| `uid` | `string` | Owning Firebase UID | Matches parent doc UID |
| `active_cycle` | `integer` | Most recently completed cycle | Between `1` and `5` |
| `completed_cycles` | `list<integer>`| Sorted list of completed cycle numbers | Elements in `[1, 2, 3, 4, 5]` |
| `is_fully_fed` | `boolean` | `true` if all 5 cycles completed | Boolean |
| `last_synthesis` | `string \| null`| Output synthesis passed to next cycle | Max 10,000 chars |
| `last_updated` | `timestamp \| string` | Last progression timestamp | Valid ISO string |

### 2.5 Chat Sessions: `/users/{uid}/chats/{session_id}`
Stores conversation histories, session titles, and message logs.

| Field | Type | Description | Constraints |
| :--- | :--- | :--- | :--- |
| `session_id` | `string` | Unique conversation UUID or timestamp ID | Max 128 chars |
| `uid` | `string` | Owning Firebase UID | Matches parent doc UID |
| `title` | `string` | User-defined or AI-generated chat title | Max 200 chars |
| `messages` | `list<map>` | Ordered list of chat messages | Max 1,000 messages |
| `created_at` | `timestamp \| string` | Creation timestamp | Valid ISO string |
| `updated_at` | `timestamp \| string` | Last message timestamp | Valid ISO string |

## 3. Firestore Security Rules (`firestore.rules`)

The `firestore.rules` file enforces a strict **deny-by-default** model:

1. **Owner-Only Client Authorization:**
   ```javascript
   function isOwner(userId) {
     return isSignedIn() && request.auth.uid == userId;
   }
   ```
   No client can read, list, create, update, or delete another user's documents or subcollections.
2. **Schema & Type Validation:** Every subcollection write is validated against strict constraints (e.g. `isValidUser`, `isValidRecord`, `isValidMemory`, `isValidFeedState`).
3. **Immutable Identity:** The `uid` field cannot be modified once set, preventing ownership reassignment.
4. **Size Bounds:** Document sizes are bounded to prevent resource exhaustion attacks.
5. **Admin SDK Trust Boundary:** Backend operations utilize the Firebase Admin SDK or genuine local database, which bypass security rules. Therefore, server routes enforce identical authorization policies at the endpoint boundary via FastAPI dependency injection.

## 4. No Anonymous Fallback & Visible Initialization Failure

In previous builds, missing credentials triggered an `AnonymousCredentials()` fallback which created an illusion of connectivity while causing silent 403 Forbidden errors when executing cloud writes.

Stroke V1 eliminates anonymous production fallback:
1. **Cloud / Production Mode:** When credentials (`FIREBASE_SERVICE_ACCOUNT_JSON`, `GOOGLE_APPLICATION_CREDENTIALS`, or Application Default) are missing or invalid, the backend raises a visible, fatal `RuntimeError`:
   ```
   RuntimeError: Cloud Firestore credentials invalid or absent (...). Set GOOGLE_APPLICATION_CREDENTIALS, FIREBASE_CREDENTIALS, FIRESTORE_EMULATOR_HOST, or set STROKE_ALLOW_OFFLINE_DB=1 for local offline mode. Anonymous production fallback is disabled.
   ```
2. **Local Offline Mode (`STROKE_ALLOW_OFFLINE_DB=1`):** When running locally without cloud credentials, Stroke initializes `LocalFirestoreClient` backed by `data/local_firestore_db.json`. This provides complete collection, document, query, batch, and transaction functionality with genuine disk persistence.

## 5. Verified Persistence vs. False Statuses

Stroke V1 eliminates fake success statuses:
- **No Fabricated Confirmations:** Endpoints never return `"database_fed": true` or `"status": "success"` if a write or commit fails.
- **Verified Batch Commits:** In both `/database/feed-cycle` and `/database/feed-5-cycles`, `batch.commit()` is explicitly executed. If an exception occurs, the endpoint raises `HTTPException(502, ...)` and halts immediately.
- **Genuine Offline Persistence:** If memory write fails to reach Cloud Firestore during network interruption, it safely falls back to local disk persistence at `data/local_user_memory/{uid}.json`, returning `"storage": "local"` and `"is_estimate": true`.

## 6. Memory System Reliability & Pre-Write Quota

### 6.1 Paginated Batch Deletion (`/memory/clear`)
- **Fixes 100-Doc Limit:** The previous implementation queried `.limit(100).stream()`, leaving documents beyond 100 undeleted while resetting the counter to 0.
- **Batched Deletion:** `/memory/clear` now iterates in batches of up to 500 documents until the collection is completely empty.
- **Safe Accounting:** Counters (`memory_bytes_used_estimate`, `memory_count`) are reset to 0 **only after** all batches succeed. If a batch fails midway, the counters are updated to reflect the records actually deleted, preserving partial consistency and returning HTTP 502.

### 6.2 Pre-Write Quota Enforcement (100 MB Limit)
- **Hard Cap:** Total estimated memory usage is capped at 100 MB (`104,857,600` bytes).
- **Pre-Write Check:** Before committing a new memory document, `record_user_firestore_memory` calculates the serialized size. If the record itself exceeds 100 MB, it is rejected immediately with a `ValueError`.
- **FIFO Eviction:** If `current_bytes + new_record_bytes > 100 MB`, the engine queries the oldest memory records ordered by `created_at` and deletes them in batches until sufficient quota is available.
- **Concurrency-Safe Accounting:** Parent document byte counters are updated atomically in the same batch write as the memory document. All byte counts are explicitly labeled as estimates (`memory_bytes_used_estimate`, `is_estimate: true`).

## 7. Sequential 5-Cycle Feed Engine

1. **Parent Document Existence:** The user root document `users/{uid}` is explicitly verified and created before any subcollection records are written.
2. **Strict Ordering:** Cycle $k$ strictly requires cycle $k-1$ to be present in `users/{uid}/feed_state/current.completed_cycles`. Out-of-order calls (e.g. requesting cycle 3 when only cycle 1 is complete) are rejected with HTTP 400.
3. **Idempotent Replay:** If cycle $k$ has already been committed, calling `/database/feed-cycle` with cycle $k$ returns the existing persisted record with `"status": "already_persisted"` and `"is_idempotent_replay": true` without re-running synthesis or creating duplicates.
4. **Atomic Ingestion:** In `/database/feed-5-cycles`, all 5 records (`STRK-BAT-001` through `005`), the feed state document, and the parent `database_fed = true` flag are committed together via `db.batch()`.

## 8. Migration Architecture (`migration_service.py`)

To migrate existing users from email-based keys to Firebase UIDs:
1. **Cryptographic Snapshot Backup:** Before executing any migration, `backup_legacy_data()` creates an immutable snapshot of all Firestore collections and local session files at `data/backups/migration_backup_<timestamp>.json`, accompanied by a SHA-256 integrity manifest.
2. **Proven Ownership:** Migration requires an authenticated Firebase ID token. The user's UID and email are derived strictly from the verified token claims.
3. **Sensitive Data Sanitization:** Passwords, password hashes, OTP codes, and ephemeral tokens are explicitly stripped and never copied to the UID document.
4. **Subcollection Migration:** Existing `records`, `chats`, and `memory` subdocuments are copied from `users/{email}/` to `users/{uid}/`.
5. **Non-Destructive & Idempotent:** Original legacy documents are preserved for auditability. Re-running migration safely skips already-migrated documents without data duplication.
